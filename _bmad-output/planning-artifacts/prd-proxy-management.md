# Product Requirements Document - 代理管理系统

**Author:** Root
**Date:** 2026-01-30
**Project Type:** 新功能开发 (Brownfield)
**Focus:** AI API代理配置与管理

---

## Executive Summary

为AI Story生成系统添加代理配置和管理功能，支持通过HTTP/HTTPS/SOCKS5代理调用外部AI API（OpenAI、Claude、Stable Diffusion等）。

**PRD目标**: 构建完整的代理管理基础设施，解决API访问受限、IP轮转、故障转移等问题。

**核心价值**:
- 🌍 **地理无限制**: 突破区域API访问限制
- 🔄 **高可用性**: 代理池故障转移，保障服务连续性
- 🔒 **安全合规**: 密码加密存储，审计日志追踪

**技术栈**: Django 3.2.15 + DRF + Vue 2.7.14 + Fernet + Celery Beat

---

## Success Criteria

### MVP成功标准（发布前必须达成）

#### 用户成功
- ✅ **管理员配置效率**: 5分钟内配置第一个可用代理（从打开Django Admin到测试连接成功）
- ✅ **开发者集成效率**: 2分钟内完成代理选择和测试（从创建项目到代理可用）
- ✅ **故障无感知**: 代理失败时，用户无感知降级到直连，无需手动干预

#### 技术成功
- ✅ **密码安全**: 密码加密解密一致性 100%
- ✅ **测试覆盖**: 单元测试覆盖率 > 80%
- ✅ **集成验证**: 集成测试覆盖核心路径（代理配置→AI调用成功）
- ✅ **向后兼容**: 无代理配置时，系统行为与原版本完全一致
- ✅ **质量门禁**: 0个严重Bug（数据丢失、安全漏洞、系统崩溃）
- ✅ **健康检查**: 健康检查任务执行成功率 > 99%

#### 性能标准
- ✅ 代理测试连接响应时间 < 3秒
- ✅ AI调用额外延迟 < 100ms（相比直连）
- ✅ 健康检查任务内存占用 < 50MB
- ✅ 并发支持: 100个并发AI调用使用同一代理，无连接池耗尽

### 业务成效（上线后3个月跟踪）

> **数据收集方法**: 从Django Admin的ProxyUsageLog表统计

#### 核心指标（成功标准）
- ✅ **采纳指标**: 代理配置数量 > 5
- ✅ **成功率**: 代理配置正确时，AI调用成功率 > 99%
  - *注：这是我们的责任边界。代理服务商质量不影响此指标。*
- ✅ **系统健康**: 健康检查任务正常运行，无异常中断

#### 参考指标（用户行为观察）
- 📊 **使用率**: 代理使用率 > 60%（启用代理的项目数 / 配置了代理的项目数）
- 📊 **活跃度**: 管理员平均每周使用Django Admin ≥ 1次
  - *注：这些是参考指标，用于了解用户使用情况，非发布门禁*

### V2成功标准（未来迭代）

#### 功能增强
- ✅ **负载均衡**: 代理池负载均衡成功率 > 95%（请求分布均匀性）
- ✅ **故障转移**: 自动故障转移（代理间切换 < 5秒）
- ✅ **协议支持**: SOCKS5协议支持（HTTP/HTTPS已在MVP实现）
- ✅ **性能监控**: 实时性能监控仪表盘（Grafana集成）
  - 告警响应时间 < 10分钟
  - 监控指标：响应时间、成功率、流量分布

#### 高级特性
- ✅ **智能路由**: 基于地理位置的智能代理选择
- ✅ **成本优化**: 代理成本统计和优化建议（目标：降低代理费用15%）
- ✅ **主动告警**: 代理故障、响应时间过长的实时通知

### Journey 3: 管理员查看使用日志（性能分析）

**📖 故事背景**:
一周后，李明想了解代理的使用情况和性能表现，以便优化配置。

**🎯 用户目标**:
分析代理使用日志，发现性能瓶颈和优化机会

**🎬 情感弧线**:
```
🤔 好奇 (想知道效果) → 📊 分析 (查看数据) → 💡 洞察 (发现趋势) → 😊 满意 (验证决策)
```

**📝 详细旅程**:

1. **日志访问** (周三下午)
   - 登录Django Admin
   - 导航到"Proxy Usage Logs"
   - 看到丰富的筛选选项：
     * 时间范围：最近1小时 / 24小时 / 7天 / 30天
     * 代理筛选：选择特定代理
     * AI提供商筛选：OpenAI / Claude / Stable Diffusion
     * 状态筛选：成功 / 失败

2. **数据分析** (14:30 PM)
   - 李明选择"最近24小时" + "OpenAI美国代理-01"
   - 看到统计摘要：
     * 总调用次数：1,245次
     * 成功率：98.7%
     * 平均响应时间：265ms
     * 失败次数：16次
   - **洞察发现**：失败主要集中在凌晨2-4点（可能是代理维护时段）

3. **深入调查** (14:35 PM)
   - 点击查看失败记录的详细信息
   - 看到错误类型：Connection timeout (14次), DNS resolution failed (2次)
   - **顿悟时刻**："代理服务商可能在凌晨维护，我应该配置一个备用代理"

4. **优化决策** (14:40 PM)
   - 李明决定配置"OpenAI美国代理-02"作为备用
   - 设置优先级：代理-01=10，代理-02=8
   - **成就感**：通过数据分析，系统将更加可靠

**✨ 关键体验点**:
- 多维度筛选的灵活性
- 统计摘要的直观性
- 详细日志的可追溯性

## Domain Analysis

### 核心概念

**ProxyConfig (代理配置聚合根)**
- 单个代理服务器的完整配置
- 包含连接信息、认证信息、状态管理

**ProxyProvider (代理提供者策略)**
- 策略模式实现
- 支持无代理、单一代理、代理池轮询

**ProxyUsageLog (使用日志值对象)**
- 记录每次代理调用的详细信息
- 用于性能分析和故障诊断

### 业务规则

1. **密码安全规则**:
   - 密码必须使用Fernet加密存储
   - 日志中不得记录明文密码

2. **健康检查规则**:
   - 5分钟内失败超过3次标记为不健康
   - 不健康的代理不参与轮询
   - Celery Beat定时检查健康状态

3. **降级规则**:
   - 代理失败后自动降级到直连
   - 记录降级事件到日志

4. **权限规则**:
   - 只有管理员可以CRUD代理配置
   - 普通用户只能查看和选择代理

## Functional Requirements

### F1: 代理配置管理

**F1.1 创建代理配置**
- 管理员可以通过Django Admin创建新代理
- 必填字段: name, protocol, host, port
- 可选字段: username, password, description, priority
- 密码自动加密存储

**F1.2 查看代理列表**
- Django Admin显示所有代理配置
- 列表字段: name, protocol, host:port, is_active, is_healthy, priority
- 支持搜索和筛选

**F1.3 编辑代理配置**
- 管理员可以修改代理信息
- 密码字段显示为占位符
- 修改后保存加密

**F1.4 删除代理配置**
- 管理员可以删除未使用的代理
- 已被项目引用的代理禁止删除（级联保护）

**F1.5 启用/禁用代理**
- 管理员可以切换 `is_active` 状态
- 禁用的代理不参与AI调用

### F2: 代理测试

**F2.1 测试连接**
- Django Admin提供"Test Connection"按钮
- 测试URL: `https://httpbin.org/ip`
- 返回代理IP或错误信息

**F2.2 前端测试**
- 项目创建页面提供"测试连接"按钮
- AJAX异步请求，不阻塞界面

### F3: 健康检查

**F3.1 定时健康检查**
- Celery Beat每5分钟执行一次
- 遍历所有启用状态的代理
- 测试连接并更新 `is_healthy` 字段

**F3.2 故障标记**
- 5分钟内失败超过3次标记为不健康
- 不健康的代理不从API返回

**F3.3 健康状态恢复**
- 连续3次成功标记为健康
- 恢复后重新参与代理池

### F4: 使用日志

**F4.1 日志记录**
- 每次AI调用记录日志
- 字段: proxy_id, ai_provider, endpoint, response_time_ms, success, error_message, timestamp

**F4.2 日志查询**
- Django Admin提供日志浏览界面
- 支持按时间、代理、AI提供商筛选
- 只读权限，禁止手动修改

### F5: AI集成

**F5.1 项目代理绑定**
- `Project` 模型添加 `proxy_id` 外键
- 可以为空（不使用代理）

**F5.2 AI客户端代理支持**
- `BaseAIClient` 构造函数接受 `proxy_id`
- 通过 `ProxyManager` 获取代理配置
- 自动构建httpx代理URL

**F5.3 降级策略**
- 代理失败后自动降级到直连
- 记录降级事件到日志

### F6: 前端集成

**F6.1 代理选择器**
- 项目创建页面显示代理下拉框
- 只显示启用且健康的代理
- 格式: "代理名称 (协议) - 状态"

**F6.2 API集成**
- 调用 `/api/v1/proxy/select/` 获取代理列表
- 调用 `/api/v1/proxy/{id}/test_connection/` 测试连接

## Non-Functional Requirements

### NFR1: Security (安全性)

**NFR1.1 密码加密**
- 使用Fernet对称加密
- 密钥存储在环境变量 `PROXY_ENCRYPTION_KEY`
- 日志中不得记录明文密码

**NFR1.2 权限控制**
- Django Admin: `IsAdminUser`
- API只读接口: `IsAuthenticated`
- 普通用户只能查看，不能修改

**NFR1.3 审计日志**
- 所有CRUD操作记录到Django Admin日志
- 包含用户、时间、操作类型

### NFR2: Performance (性能)

**NFR2.1 响应时间**
- 代理测试连接 < 5秒
- 健康检查超时 = 5秒
- AI调用额外延迟 < 100ms

**NFR2.2 并发支持**
- 支持至少100个并发AI调用使用同一代理
- 使用httpx连接池管理

**NFR2.3 资源消耗**
- 健康检查任务 < 10MB内存
- 日志记录不超过100MB/月

### NFR3: Reliability (可靠性)

**NFR3.1 降级策略**
- 代理失败100%降级到直连
- 不影响现有AI调用流程

**NFR3.2 数据一致性**
- 密码加密解密必须一致
- 日志记录原子性

**NFR3.3 错误处理**
- 所有代理错误记录到日志
- 用户看到友好错误提示

### NFR4: Maintainability (可维护性)

**NFR4.1 代码质量**
- 遵循SOLID原则
- 单元测试覆盖率 > 80%
- 代码符合PEP8规范

**NFR4.2 文档完整**
- API文档（DRF自动生成）
- 安装和配置指南
- 故障排查手册

**NFR4.3 向后兼容**
- 无代理配置时保持原有行为
- 数据库迁移可回滚

### NFR5: Usability (可用性)

**NFR5.1 Django Admin界面**
- 列表、搜索、筛选功能完善
- 表单验证和错误提示清晰
- 批量操作支持

**NFR5.2 前端体验**
- 代理选择器易于使用
- 测试连接实时反馈
- 加载状态提示
