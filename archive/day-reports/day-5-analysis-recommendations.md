## ⚠️ 挑战与问题

### 问题1: WebSocket测试复杂性

**现状:** 10个测试，6个通过，4个失败
**问题:** Channels消费者需要复杂的异步Mock配置
**影响:** Epic 3 (实时通信) 进度受限

**根本原因:**
1. Channels消费者属性在connect()中设置，不在__init__
2. 需要Mock大量的异步方法（accept, send, Redis连接）
3. 异步任务调度顺序难以测试

**解决方案选项:**

**方案A: 使用真实Redis集成测试（推荐）**
```python
# 使用pytest-asyncio和真实Redis
@pytest.mark.asyncio
async def test_websocket_with_real_redis():
    # 启动真实Redis容器
    # 使用WebsocketCommunicator连接
    # 发布消息到Redis
    # 验证WebSocket接收
```
- 优点: 测试真实场景，配置简单
- 缺点: 需要Redis依赖，测试速度慢

**方案B: 使用channels.testing.WebsocketCommunicator**
- 优点: 更接近真实WebSocket连接
- 缺点: 学习曲线陡峭

**方案C: 延后处理（备选）**
- 优点: 节省时间，优先完成其他任务
- 缺点: Epic 3进度滞后

**推荐:** 先完成方案A（集成测试），如果时间充裕再尝试方案B
